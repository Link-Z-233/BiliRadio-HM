# Feature Specification: v0.8-part1 随机播放去重与随机下一首播放

**Status**: Draft
**Input**: User description: "将已播内容从随机播放下一首的范围内排除；实现随机模式下「下一首播放」"

## Overview

随机模式的条目级抽取从「有放回等概率」改为分层排除抽取：本会话已起播的条目不再被抽中；候选耗尽后从未完播条目中重抽；全部条目完播后停止自动连播。同时，源页「下一首播放」插入的条目在随机模式下登记为「指定下一首」，按插入顺序真正兑现为下一首播放，不再被随机抽签吞没。附带应用版本号升至 0.8.0。

## User Scenarios & Testing

### User Story 1 - 随机播放不重复已播条目 (Priority: P1)

随机模式下连续点「下一首」，本会话已听过的条目不再被抽中，一遍听完候选池中的全部条目而无重复。

**Why this priority**: 现状有放回抽签导致随机模式反复播已听内容，是本次功能的核心出发点。

**Independent Test**: 随机模式全新会话连续切歌 N 次（N ≤ 候选条目数），验证抽中条目两两不同。

**Acceptance Scenarios**:

1. **Given** 歌单 10 个未完播条目、随机模式、全新会话，**When** 从任意条目起连续点「下一首」9 次，**Then** 播过的 10 个条目两两不同
2. **Given** 条目 A 刚起播即被跳过，**When** 再点「下一首」，**Then** 不会再抽中 A（直至重抽轮）
3. **Given** 随机抽中多P 条目且其分P 未播完，**When** 点「下一首」，**Then** 组内连播继续下一分P，排除机制不影响组内连播
4. **Given** 有持久化完播标记的条目（此前会话已听完），**When** 本会话随机抽取，**Then** 该条目不在候选池中（完播排除跨会话生效）
5. **Given** 用户手动点选队列中某条目起播，**When** 随机模式继续切歌，**Then** 该条目同样被标记已播，不再被抽中

---

### User Story 2 - 已播耗尽后从未完播重抽、全完播停止 (Priority: P2)

候选池中所有条目都起播过之后，随机模式优先重抽没听完的条目；全部条目完播后停止自动连播。

**Why this priority**: 「不重复」的完整语义需要定义耗尽后的行为，避免无限重播已听完内容或突然死循环。

**Independent Test**: 小歌单（2-3 条目）随机连播到底，验证重抽只覆盖未完播条目、全完播后停止。

**Acceptance Scenarios**:

1. **Given** 歌单全部条目已起播、其中 3 个未完播，**When** 点「下一首」，**Then** 从 3 个未完播条目中随机抽一个
2. **Given** 重抽轮中某条目听完并获得完播标记，**When** 下一次抽取，**Then** 该条目不再进入候选
3. **Given** 歌单全部条目均有完播标记，**When** 当前条目自然播完，**Then** 停止自动连播，不再切下一首
4. **Given** 全部完播已停止，**When** 手动点「下一首」，**Then** 维持现状回退行为（重播当前条目），不自动开启新一轮重抽

---

### User Story 3 - 随机模式「下一首播放」兑现 (Priority: P3)

用户从源页单击入队（设置开启「下一首播放」）或多选「下一首播放」按钮插入条目，随机模式下插入的条目真正作为下一首按插入顺序播放。

**Why this priority**: 现状随机模式下插入位置紧邻当前条目但无语义，用户显式指定的播放意图被随机抽签吞没。

**Independent Test**: 随机模式播放中，源页「下一首播放」插入 1 个条目后点「下一首」，验证播放的是插入条目。

**Acceptance Scenarios**:

1. **Given** 随机模式正在播单P 条目，**When** 源页「下一首播放」插入条目 X，**Then** 点「下一首」播放的是 X 而非随机抽取结果
2. **Given** 随机模式正在播多P 条目的中间分P，**When** 插入 X 后点「下一首」，**Then** 先组内连播播完当前视频剩余分P，再播 X（与顺序模式插入位语义一致）
3. **Given** 多选插入 X/Y/Z 三个条目，**When** 连续点「下一首」3 次，**Then** 按插入顺序播放 X→Y→Z
4. **Given** 插入的条目已在歌单别处（命中去重），**When** 插入，**Then** 维持现状：提示去重跳过，不移动、不登记指定下一首
5. **Given** 用户先按「上一首」回溯再插入 X，**When** 连续点「下一首」，**Then** 先重放前进轨迹条目，再播 X（见 Assumptions 优先级链）

应用版本号随本批功能升级，标识 v0.8 首批变更。

**Why this priority**: 用户要求的随批事项，无独立用户价值。

**Independent Test**: 检查应用版本信息显示 0.8.0。

**Acceptance Scenarios**:

1. **Given** 当前版本 0.7.0 / versionCode 7000，**When** 本批实施完成，**Then** 版本信息为 0.8.0 / versionCode 8000

### Edge Cases

- 随机抽取时候选池为空且全部条目完播：自动连播停止；手动切歌回退重播当前（US2 场景 4）
- 歌单中途增删条目：已播标记按复合键（bvid+page 归一化）判定，条目移除后标记悬空无效，同键条目重新入队则会话内仍视为已播
- 应用重启：会话已播集与指定下一首队列丢失（回到第一轮全量候选），完播排除保留
- 完播标记播放中实时写入：条目听到结尾即获得完播标记，下一次抽取即刻排除
- prepare 失败的条目：不算起播，不写入已播标记（下轮仍可被抽中）
- 顺序/倒序模式及列表页拖拽/置顶操作：行为零变化

## Requirements

### Functional Requirements

- **FR-001**: 随机模式条目级抽取的候选池 MUST 为「未完播条目 − 本会话已播条目」；未完播判定沿用既有持久化完播标记，跨会话生效
- **FR-002**: 任何来源的起播（随机抽中、手动点选、轨迹回溯、指定下一首、组内连播）MUST 写入会话已播标记；起播判定为真正开始装载播放，prepare 失败不标记
- **FR-003**: 候选池为空且仍存在未完播条目时，系统 MUST 清空会话已播标记并在未完播条目中重新抽取
- **FR-004**: 未完播条目也为空（全部完播）时，当前条目自然播完后 MUST 停止自动连播；手动切歌维持现状回退，不自动重洗
- **FR-005**: 源页 insertAfterCurrent 插入路径（单击入队「下一首播放」设置、多选「下一首播放」按钮）插入的新条目 MUST 按插入顺序登记为「指定下一首」队列
- **FR-006**: 随机模式「下一首」选取优先级 MUST 为：前进轨迹重放 > 组内连播 > 指定下一首（FIFO）> 排除式随机抽取 > 现状回退（重播当前）
- **FR-007**: 指定下一首条目在起播（消费）、移出歌单、歌单清空重生成时 MUST 从队列清除；命中去重被跳过的条目 MUST NOT 登记
- **FR-008**: 会话已播集与指定下一首队列 MUST NOT 持久化（重启即失效）；完播排除依托既有持久化完播标记
- **FR-009**: 顺序/倒序模式的全部行为、列表页拖拽/置顶移动、prev() 轨迹回溯机制 MUST 保持现状零变化
- **FR-010**: 应用版本号 MUST 升至 versionName 0.8.0 / versionCode 8000
- **FR-011**: 源页插入命中去重 MUST 维持现状跳过语义（提示去重、不移动、不登记指定下一首）

### Key Entities

- **会话已播集**: 本会话已起播条目的复合键集合（bvid+page 归一化口径），条目级粒度（多P 条目任一分P 起播即整条目已播），内存态、不持久化
- **完播排除**: 对既有持久化完播标记的直接引用，条目级粒度（全部分P 完播才算完播排除）
- **指定下一首队列**: 源页 insertAfterCurrent 插入产生的有序复合键队列（FIFO），内存态、不持久化

## Success Criteria

- **SC-001**: 随机模式全新会话连续切歌至候选耗尽，无任何条目重复起播
- **SC-002**: 已播耗尽后的重抽仅覆盖未完播条目；全部条目完播后自动连播停止
- **SC-003**: 源页「下一首播放」插入的条目在随机模式下按插入顺序兑现为下一首播放（组内连播衔接场景除外，按优先级链顺序衔接）
- **SC-004**: 顺序/倒序模式、列表页既有操作、prev() 回溯行为与升级前完全一致
- **SC-005**: 构建验证通过（本批默认 build-only）

## Assumptions

- 起播即算的「起播」= 真正开始装载播放（playIndex 生效），prepare 失败不标记
- 完播判定沿用现有完播标记机制（progress=-1），本功能不新增完播判定逻辑
- 条目级排除粒度：多P 条目任一分P 起播即整条目已播；全部分P 完播才算完播排除
- 重抽轮起播位置沿用现状：条目最小页下标起播，不做「从未完播分P 继续」
- 指定下一首排在前进轨迹重放与组内连播之后、随机抽取之前：既偿还「欠着的续播」（回溯重放、当前视频剩余分P），又先于任何新随机抽取兑现用户显式指定；与现状优先级链（前进重放 > 组内连播）零冲突
- 歌单清空重生成时会话已播集、指定下一首队列随之重置（与 shuffleHistory 现状一致）
- 指定下一首条目被点播起播同样视为消费（队列出队），不重复兑现
- 全完播停止后手动「下一首」维持现状回退（重播当前），不自动开启新轮
