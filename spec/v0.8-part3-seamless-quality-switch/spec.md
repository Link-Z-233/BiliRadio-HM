# Feature Specification: v0.8-part3 无缝音质切换

**Status**: Draft
**Input**: 换网/手动切音质时总会顿一下；改为网络条件变更时的无缝音质切换（双播放器方案），自动+手动路径均覆盖。

## Overview

换档（网络类型稳定切换自动换档 / 面板手动换档）期间，当前出声流全程不间断，目标音质流在独立通道旁路预加载至当前播放进度，就绪后瞬间交接，消除现有「释放旧实例→重建→prepare→seek」路径的可感知停顿。目标流加载失败时整体丢弃，旧流无感知继续播放，回滚天然免费。

## User Scenarios & Testing

### User Story 1 - 换网自动换档无停顿 (Priority: P1)

播放中网络在 Wi-Fi↔流量间稳定切换（既有 3 秒防抖触发器），系统按新网络默认档自动换流，声音全程连续，用户听不到任何中断或提示音以外的变化。

**Why this priority**: 换网场景是本需求的原始动因，也是自动路径的核心价值；现有 FR-010 已覆盖触发与档位选择，本轮增量全部落在「消除顿挫」上。

**Independent Test**: 播放中开关 Wi-Fi，观察音频是否连续、档位是否切换为新网络默认档。

**Acceptance Scenarios**:

1. **Given** Wi-Fi 下以 192K 播放中，**When** 稳定切换到流量（默认档 64K），**Then** 音频无停顿地过渡到 64K 流，进度连续，界面档位显示更新
2. **Given** 流量下以 64K 播放中，**When** 稳定切回 Wi-Fi（默认档 192K），**Then** 音频无停顿地升回 192K 流
3. **Given** 新网络默认档与当前实际档相同，**When** 网络稳定切换，**Then** 不触发换流（沿用既有同档跳过）

---

### User Story 2 - 手动切档无停顿 (Priority: P2)

播放中用户在音质面板手动选择其他档位，与自动换档同享无缝机制，声音全程连续。

**Why this priority**: 手动切档与自动换档走同一条换流路径，复用同一机制增量成本近零；单列一 Story 保证验收独立。

**Independent Test**: 播放中打开音质面板切换档位，听感无停顿，进度连续。

**Acceptance Scenarios**:

1. **Given** 播放中（任意档位），**When** 面板选择另一可用档位，**Then** 音频无停顿过渡到新档，进度连续，面板选中态更新
2. **Given** 暂停状态切档，**When** 选择另一档位，**Then** 换流完成后仍为暂停态、进度不变（无声路径不要求双流，但进度与暂停语义必须保持）

---

### User Story 3 - 换档失败旧流无感知 (Priority: P3)

目标流解析或加载失败（网络异常、档位不可用、预加载超时），旧流以原音质、原进度继续播放不被打断，界面给出失败提示。

**Why this priority**: 双播放器方案下失败路径的天然属性，也是相对现状（换流阶段失败需恢复链重建）的体验升级；单列以保证失败语义被显式验收。

**Independent Test**: 播放中切档并在解析阶段制造失败（如断网后立即切档），旧流继续出声。

**Acceptance Scenarios**:

1. **Given** 播放中，**When** 切档且新流解析失败，**Then** 旧流原档位原进度继续播放，界面提示失败，播放状态字段一致
2. **Given** 播放中，**When** 切档且新流预加载超时或中途出错，**Then** 同上——旧流全程未受影响，无恢复重建、无静音窗口

---

### Edge Cases

- 换档进行中用户再次切档（连点档位）：以最后触发为准，前一未完成的新流预加载被放弃或替换，不出现交错换流
- 换档进行中用户暂停/恢复/seek/切歌：操作即时作用于当前出声流；未完成的预加载按最新意图收敛，切歌/停止时直接丢弃
- 换档进行中旧流自然播完（completed）：按既有完播链路处理，放弃未完成的交接
- 交接点音频重叠：新流先起声、旧流随即停止，允许毫秒级重叠，不允许静音缝隙
- 锁屏/后台（AVSession 在播、后台长连播）下发生换网：换档行为与前台一致
- 双 AVPlayer 并存的设备资源占用：换档结束后旧实例必须释放，不长期驻留双实例

## Requirements

### Functional Requirements

- **FR-001**: 播放中触发换档（网络稳定切换自动档 / 面板手动档）时，系统必须在旧流持续出声的前提下，于独立播放通道预加载目标音质流并定位到当前播放进度
- **FR-002**: 目标流就绪后执行交接：新流自交接点续播，旧流停止并释放；交接不得产生用户可感知的静音间隙
- **FR-003**: 目标流解析或加载失败（含超时）时，系统保持旧流以原音质、原进度继续播放，界面提示失败，不做无限重试
- **FR-004**: 换档全程中的并发与用户操作遵循既有「最后触发者为准」令牌语义：任何时刻只有一个在途换档，新触发使旧在途结果失效
- **FR-005**: 暂停状态下切档走无声换流路径：完成后保持暂停态、进度不变、档位更新
- **FR-006**: 现有换档边界保持不变：durl 兜底流、预加载进行中、cid 无效时自动换档不触发（手动路径沿用现状提示）
- **FR-007**: 交接完成后，播放历史、心跳、媒体会话（锁屏/控制中心）的曲目与进度语义与现状一致（同一曲目内换档不产生新历史记录、进度连续）

### Key Entities

无新增持久化实体。音质档位（QualityTier）、音轨（AudioTrack/ResolvedAudio）、网络默认档设置（Wi-Fi/流量分键）、播放进度沿用现有模型。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 播放中 Wi-Fi↔流量稳定切换自动换档，全程听感无停顿、无静音缝隙
- **SC-002**: 播放中手动切档，全程听感无停顿
- **SC-003**: 换档失败时旧流 100% 保持原音质原进度继续播放（无恢复重建窗口）
- **SC-004**: 换档全程任意用户操作（再切档/暂停/seek/切歌）不产生错播、串音或进度丢失

## Assumptions

- 触发器沿用现有稳定网络切换监听（3 秒防抖），不新增带宽劣化/卡顿检测
- 自动换档目标档沿用现有「按网络默认档」逻辑；手动切档写回逻辑不变（按当前网络写回对应默认档键）
- 换档仅适用 dash 音轨流；durl 兜底流不参与
- 目标设备支持双 AVPlayer 实例短暂并存（一出一备）
- 既有「已切换 音质名」状态提示语义保留，交接完成后落定
