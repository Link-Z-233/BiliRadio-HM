# Feature Specification: 音量均衡（服务端响度归一）+ 设置页重排（账号组音质提示/网络设置独立组）

**Status**: Draft
**Input**: ①用户需求「再加一个音频响度均衡的功能」。经澄清与前置实测拍板：方案 = 服务端响度数据 + 静态增益（官方 PC 同款）；单档开关；设置页播放设置组入口；默认关闭。API 依据 `BILI_NOTES.md` §3.14（本功能前置探针）。②用户需求「把这个只在设置页展示的提示挪到账号组底部。原位置感觉像在仅在 Wi-Fi 环境播放内。将网络设置独立为一个组吧」——音质提示归属修正 + 播放设置组拆分（原 v0.8-part6-settings-regroup 内容并入本轮）。

## Overview

不同视频录音响度差异大（实测样本 -7.4 ~ -13.5 LUFS，差距近 7 dB），连播时忽大忽小。本功能引入「音量均衡」：取流时从 playurl 响应解析 B 站服务端预计算的响度测量数据（`volume` 对象），按官方 PC 同款公式 `gain_dB = target_i − measured_i` 计算静态增益，经播放器响度增益接口应用到当前曲目，使各视频听感响度统一到 B 站目标响度（-14 LUFS）。设置页「播放设置」组提供开关（默认关闭）；无响度数据或增益不可用时静默不增益，播放零干扰。

设置页「播放设置」组当前混装异质设置：播放行为开关、按网络分类的默认音质、网络播放策略、队列行为各占数行，未登录/非会员音质提示夹在「移动网络默认音质」与「仅在 Wi-Fi 环境播放」之间，视觉上像后者的说明。本轮将该提示挪到账号组卡片内底部（提示本质是登录/会员态说明），并把按网络分类的三项设置析出为独立「网络设置」组，恢复分组语义。

## User Scenarios & Testing

### User Story 1 - 开启后自动响度对齐 (Priority: P1)

用户在设置页开启「音量均衡」后，播放任何有响度数据的视频时，系统自动把过响内容压低、偏轻内容维持（目标响度 -14 LUFS 由服务端统一下发），连续切换不同 UP/不同类型的视频听感响度一致，不再出现「下一首突然炸耳」。

**Why this priority**: 响度对齐是本功能的核心价值，其余故事都是它的开关控制与兜底。

**Independent Test**: 开启开关后播放任一有响度数据的视频（可用过响的游戏 PV 类内容），通过日志中的 gain 值与实际听感验证。

**Acceptance Scenarios**:

1. **Given** 开关开启且视频响度数据为 `measured_i=-7.4`，**When** 开始播放，**Then** 应用约 `-6.6 dB` 增益，听感响度与 `-13.5` 类视频一致。
2. **Given** 开关开启且视频 `measured_i` 已接近 `target_i`，**When** 播放，**Then** 增益绝对值极小（约 0.5 dB 量级），听感与原始几乎无差。
3. **Given** 开关开启，**When** 连续播放两个响度差异大的视频，**Then** 切换瞬间听感响度过渡平缓，无跳变。

---

### User Story 2 - 开关切换即时生效 (Priority: P2)

均衡生效中用户关闭开关，当前曲目增益立即恢复原始响度（不中断播放、不重新取流）；关闭状态开启开关，当前曲目立即应用增益（响度数据已随取流获得）。后续曲目按最新开关状态执行。

**Why this priority**: 开关是用户对功能的完全控制权，必须即时可逆。

**Independent Test**: 播放中切换开关，验证响度即时变化且播放不中断。

**Acceptance Scenarios**:

1. **Given** 均衡生效中（增益非 0），**When** 关闭「音量均衡」，**Then** 当前曲目增益立即归零，播放不中断。
2. **Given** 均衡关闭中播放含响度数据的视频，**When** 开启开关，**Then** 当前曲目立即应用对应增益，播放不中断。
3. **Given** 开关状态变化，**When** 下一首播放，**Then** 按最新开关状态应用或不应用增益。

---

### User Story 3 - 无数据与异常兜底 (Priority: P3)

开启均衡但视频无 `volume` 数据（老视频、durl 兜底链、特殊稿件）、数据形态异常、或增益应用失败时，系统一律静默按原始响度播放：无报错、无提示、播放不中断，仅日志记录。

**Why this priority**: 兜底保证功能永不劣化播放体验；价值低于前两者但为上线必备。

**Independent Test**: 播放无响度数据的视频，验证零干扰正常播放。

**Acceptance Scenarios**:

1. **Given** 开关开启且取流响应无 `volume` 对象，**When** 播放，**Then** 原始响度播放，无任何用户可见异常。
2. **Given** 开关开启且 `volume` 字段形态异常（缺字段/越界值），**When** 播放，**Then** 视为无数据，静默不增益。
3. **Given** 增益应用接口调用失败，**When** 播放，**Then** 播放不受影响，失败记入日志。

---

### User Story 4 - 设置页重排：音质提示归位账号组 + 网络设置独立成组 (Priority: P1)

用户打开设置页，未登录/非会员音质提示展示在账号组卡片内底部（提示本质是登录/会员态说明，不再被误读为「仅在 Wi-Fi 环境播放」行的说明）；「Wi-Fi 默认音质」「移动网络默认音质」「仅在 Wi-Fi 环境播放」三行从「播放设置」组析出为紧随其后的独立「网络设置」组，分组语义恢复清晰。

**Why this priority**: 提示归属错误与分组混装同属设置页结构问题，一次重排一并修复。

**Independent Test**: 三种登录态打开设置页核对提示位置与组结构；操作迁移三行确认功能不变。

**Acceptance Scenarios**:

1. **Given** 未登录，**When** 打开设置页，**Then** 账号组卡片内底部（二维码块之后）显示「未登录时最高 64K，登录后可用更高音质」，原「播放设置」组内不再出现该提示。
2. **Given** 登录且非大会员，**When** 打开设置页，**Then** 账号组底部（取消收藏提醒行之后）显示「192K/Hi-Res/杜比需大会员」；大会员或冷启动恢复占位期间则无提示。
3. **Given** 任意登录态，**When** 打开设置页，**Then** 出现组标题「网络设置」，组内依次为 Wi-Fi 默认音质、移动网络默认音质、仅在 Wi-Fi 环境播放，位于「播放设置」组之后；「播放设置」组恰含启动时自动播放、后台打断续播、音量均衡、单集插入位置四行。
4. **Given** 任意登录态，**When** 操作网络设置组三行（切开关/开弹层选档），**Then** 持久化、弹层（含顶部 notice）、取值展示与重排前一致。

---

### Edge Cases

- `measured_i` 低于可疑阈值（服务端下发 `undersized_target_i=-28`）：官方 PC 同款守卫，视为测量无效，不增益。
- 防削波：计算出的增益若使 `measured_tp + gain > 0 dBFS`，增益钳制到不放大峰值越限（衰减方向不受限）。
- 换流场景（音质换档旁路交接、切歌）产生的新播放器实例必须重新应用增益，避免增益丢失或错配。
- 增益超出播放器接口有效区间（[-90, +24] dB）时钳制到边界。
- 播放历史、队列、收藏、音质档位等既有链路不受开关状态影响。
- 冷启动恢复中（账号占位「正在恢复登录状态…」）：登录态未知 → 不展示音质提示，避免闪现错误文案。
- 登录/登出、会员态变化瞬时切换：提示随登录态立即刷新（沿用现有响应式刷新，无额外逻辑）。
- 音质选择弹层（点开任一音质行后的 OptionSheet）：其顶部 notice 与设置页提示文案同源但独立展示，本轮不调整。

## Requirements

### Functional Requirements

- **FR-001**: 取流系统 MUST 能从 playurl 响应获取响度数据——请求携带 `voice_balance=1`（响应才下发 `volume` 对象，实测见 BILI_NOTES §3.14）。
- **FR-002**: 系统 MUST 解析 `volume` 对象的 `measured_i`、`measured_tp`、`target_i` 及 `multi_scene_args.undersized_target_i` 字段为严格类型模型，形态异常视为无数据。
- **FR-003**: 均衡开启时系统 MUST 按 `gain_dB = target_i − measured_i` 计算增益，并应用守卫：`measured_i < undersized_target_i` 跳过；防削波钳制；接口区间钳制。
- **FR-004**: 「音量均衡」开关 MUST 持久化（AppStore 偏好键，入 Constants 唯一真相源），默认关闭。
- **FR-005**: 开关切换 MUST 对当前播放曲目即时生效（恢复/应用增益），不中断播放、不重新取流；对后续曲目按最新状态执行。
- **FR-006**: 无数据/解析失败/增益应用失败 MUST 静默降级为原始响度，仅日志记录，无用户可见异常。
- **FR-007**: 切歌与换流（含音质换档旁路交接）时系统 MUST 对新曲目重新解析并应用（或不应用）增益。
- **FR-008**: 均衡关闭时系统行为 MUST 与现版本完全一致（不解析依赖、不改变取流行为）。
- **FR-009**: 音质提示 MUST 挪至账号组卡片内底部，条件渲染与现状一致（未登录 → 64K 提示、非会员 → 192K/Hi-Res/杜比提示、大会员与冷启动占位 → 无提示），「播放设置」组内原位置移除。
- **FR-010**: 「网络设置」独立组 MUST 含 Wi-Fi 默认音质、移动网络默认音质、仅在 Wi-Fi 环境播放三行，位于「播放设置」组之后；「播放设置」组保留启动时自动播放、后台打断续播、音量均衡、单集插入位置四行；页面其余组序不变。
- **FR-011**: 重排 MUST 零功能回归——toggle 持久化键、音质弹层触发与顶部 notice、取值展示、divider「非末行有、末行无」惯例全部不变。

### Key Entities

- **响度数据（volume）**: playurl 响应内服务端预计算的对象，含测量值（`measured_i/lra/tp/threshold`）与目标值（`target_i/tp/offset`）及多场景参数（`multi_scene_args`，值为字符串 map）；随每次取流刷新，不缓存。
- **均衡开关**: 播放设置布尔项，持久化；控制增益计算与应用的唯一开关。

## Success Criteria

- **SC-001**: 开启后，任一有响度数据的视频按公式获得增益并应用（日志可查 gain 值），响度统一到服务端目标。
- **SC-002**: 播放中切换开关 100% 即时生效，播放零中断。
- **SC-003**: 无数据/异常内容 100% 正常播放，零新增用户可见报错。
- **SC-004**: 开关关闭时全链路行为与现版本一致，零回归。
- **SC-005**: 三种登录态（未登录/非会员/会员）下账号组底部提示展示正确，原位置无残留。
- **SC-006**: 「网络设置」组恰含三行且全部功能可用，「播放设置」组恰含四行，设置页其余部分零回归。

## Assumptions

- 响度数据命中率依据 §3.14 实测（2019/2026 两代视频均完整下发，匿名即可）；老视频个案（av170001 playurl -400）无法验证，由 FR-006 兜底覆盖。
- 播放器响度增益接口（`setLoudnessGain`，API 21+，本项目 SDK 26 可用）满足前置条件（`audioRendererInfo.usage` 为 MUSIC/MOVIE/AUDIOBOOK）——现有播放器配置在 plan 阶段核对，不满足时补配置。
- 单档模式（标准，`target_i` 即 `normal_target_i`）；高动态模式、手动增益微调、按 UP/按视频记忆增益均不在本轮范围（用户已排除）。
- 增益对用户黑盒（不展示 dB 值），对齐官方客户端交互。
- 设置文案对齐官方语义：「音量均衡」，副题「自动平衡不同视频间的音量大小」。
- 组标题定为「网络设置」；提示样式沿用现主题色小字形态，仅位置变化。
- 「单集插入位置」属队列行为，留在「播放设置」组。
- 账号组底部提示在未登录分支位于二维码块之后（组卡内最底），已登录分支位于「取消收藏提醒」行之后。
- v0.8-part2 分组重组的组序语义延续：本轮只动「播放设置」组的内部拆分，不重排组间顺序。

## Open Questions

- `voice_balance=1` 是否与开关状态解耦恒携带（便于开关即开即用，代价为响应多一个字段）——plan 阶段决定。
- durl 兜底链（fnval=0）是否同样携带 `voice_balance`、是否下发 `volume`——未实测（§3.14 未实测项③），默认按「无数据兜底」处理。
- `setLoudnessGain` 是否内建平滑过渡、失败形态（状态不允许时 Promise reject）——plan 阶段以本机 SDK `.d.ts` 与真机行为核对。
